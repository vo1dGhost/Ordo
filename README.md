# Ordo

Ordo 是一款原生 macOS 菜单栏窗口管理器。它使用修饰键与鼠标移动完成窗口缩放、八向排布和自由移动；不读取普通键盘内容，也不会截断系统输入。

当前版本面向本机开发与使用：没有登录启动、安装包、公证、App Store 发布、网络服务或遥测。

文档入口：[仓库协作约定](AGENTS.md) · [图标资源说明](Artwork/README.md) · [本机验证记录](docs/VALIDATION.md)。

在菜单栏选择“打开 Ordo…”可打开或再次前置主窗口；窗口已最小化时会先恢复。主窗口保持普通窗口层级，切换到其他 App 后不会持续置顶，Ordo 仍不显示 Dock 图标。

## 功能

| 模式 | 默认组合键 | 操作 |
| --- | --- | --- |
| 调整大小 | `⌥⇧` | 按住组合键并移动鼠标，固定窗口左上角，改变右下角位置 |
| 窗口排布 | `⌘⌃` | 按住组合键，以起点标记为参照向八个方向移动鼠标，预览布局，松开任一必要修饰键后应用 |
| 移动窗口 | `⌃⇧` | 按住组合键并移动鼠标，窗口以相对位移跟随鼠标 |

按下组合键时，Ordo 会锁定鼠标下方可见区域对应的窗口；同一次手势中不会更换目标。移动超过 4 pt 后，Ordo 会尝试将该窗口提到前方并给予键盘焦点，再开始移动、缩放或排布；仅按下再松开不会改变窗口、焦点或层级。前置过程只针对命中的窗口，不会主动带起或重排同一 App 的其他窗口；被完全遮挡的窗口仍无法直接命中。

单窗口前置先使用 `AXRaise`，再按窗口属性可写性准备主窗口与键盘焦点；确认目标身份后，通过公开旧接口 `SetFrontProcessWithOptions` 的单前窗选项激活目标 App，不使用整 App 激活兜底。该接口已被 Apple 标记为弃用，效果受目标 App 和 macOS 窗口层级约束；当前 Space 内的普通窗口需要真实多窗口验收，不能保证跨越浮动面板或阻止目标 App 自身在激活时调整窗口。目标不支持前置、调用超时或身份无法确认时，Ordo 会跳过进程激活并继续几何操作；权限撤销或窗口失效等硬错误仍会安全终止本次手势。

Ordo 自身的标准窗口也使用同一套手势和 AX 写入链路，不再按进程身份排除；固定尺寸、最小尺寸或不可写属性仍会按窗口自身约束返回可恢复错误。

若置前调用返回“属性不支持”（`AX -25205`），Ordo 会跳过焦点切换并继续移动、缩放或排布，不再因此中止手势；此兼容处理仅限置前调用，不忽略实际位置或尺寸写入失败。

排布手势成功锁定目标窗口后，会在起始指针位置显示固定的 40 pt 八瓣玻璃标志，以冰蓝分瓣环呼应 Ordo 图标，中央保持透明。离起点超过 24 pt 后进入选择，对应的一瓣高亮；回到 16 pt 内会清除选择并恢复八瓣等亮，标志保留到手势结束。方向切换使用 120 ms 明暗过渡，启用“减少动态效果”时即时更新；启用“减少透明度”时使用不透明配色。八个方向对应以下布局：

| 方向 | 布局 |
| --- | --- |
| `←` / `→` | 左右半屏 |
| `↑` | 铺满当前屏幕可见区域，不进入原生全屏 Space |
| `↓` | 当前屏幕可见区域宽、高各 75%，居中 |
| `↖` / `↗` / `↘` / `↙` | 对应角落的四分之一屏 |

排布使用手势起点所在屏幕的实时可见区域，自动避开菜单栏、Dock 和刘海。移动与手动缩放可以跨屏。

## 系统要求

- macOS 14 或更高版本
- 包含 macOS 26 SDK 的 Xcode 26 或更高版本（当前使用 Xcode 26.6 验证）
- 辅助功能权限
- 本机构建需要团队 `ND3SVRRF43` 的有效 Apple Development 证书及私钥

工程配置关闭了 App Sandbox，并启用 Hardened Runtime。控制其他 App 的窗口依赖 macOS 辅助功能 API，这是预期配置。

Finder 等少数应用可能通过 `AXEnhancedUserInterface` 对辅助功能窗口写入再施加系统过渡。排布期间，Ordo 仅在该属性原本开启时临时关闭并随后恢复；属性不可用时会直接沿用标准 AX 路径。该兼容行为不增加权限、不记录应用身份，但依赖未公开的 AX 属性，可能随 macOS 更新失效。

macOS 26 或更高版本使用系统 `glassEffect`；macOS 14–25 使用标准 Material 回退。预览、主界面和权限引导会尊重“减少动态效果”和“减少透明度”。

## 构建与启动

日常修改后，在项目根目录执行一键更新：

```bash
./scripts/dev-update.sh
```

脚本先在 `build/Updates/` 下独立构建 Release 并验证签名、团队、Bundle ID 和必要配置，再通过 `NSRunningApplication` 请求当前 `build/Ordo.app` 正常退出，等待清理完成。随后将旧版归档到 `build/Archive/` 下带时间戳的目录，把新版放到固定路径 `build/Ordo.app`，通过 Launch Services 启动并核对 PID 与实际执行路径。

构建或验签失败不会影响运行中的旧版；旧版退出超时则停止更新，不强制结束进程。替换或启动失败时保留失败候选并尝试恢复旧版；若无法安全完成恢复，脚本会报告需处理的路径。失败候选与日志保留在 `build/Updates/`，旧版归档不会自动删除。脚本禁止并发更新；遇到 `build/.dev-update.lock` 遗留锁时不会自动清除，应先确认对应更新进程已结束，再将锁目录移走归档。若发现其他路径运行的 Ordo，脚本会停止并提示位置，请先从那个实例的菜单栏正常退出。

App 与测试 target 的 Debug、Release 均使用团队 `ND3SVRRF43` 的 `Apple Development` 手动签名。钥匙串中必须有该团队有效的开发证书及私钥；不可用时构建失败，不回退到临时签名。证书续期时保持同一团队的开发签名，并重新验证更新后的权限延续性。

完整测试单独运行，更新命令不会每次重复测试。若仅需验证构建而不更新正在运行的 App，可将产物放到独立目录：

```bash
xcodebuild \
  -project Ordo.xcodeproj \
  -scheme Ordo \
  -configuration Release \
  -destination 'platform=macOS' \
  -derivedDataPath "$PWD/build/VerificationDerivedData" \
  CONFIGURATION_BUILD_DIR="$PWD/build/Verification" \
  build
```

也可以用 Xcode 打开 `Ordo.xcodeproj`，选择 `Ordo` Scheme 和 `My Mac` 后按 `⌘R` 调试。Xcode Run 使用另一产物路径，运行前须先正常退出同 Bundle ID 的其他 Ordo 实例；日常使用仍通过更新脚本启动固定路径。

Ordo 设置了 `LSUIElement`，启动后不会显示 Dock 图标。菜单栏提供启用开关、主界面入口和退出操作；权限与活动日志位于主界面。

## 菜单栏图标与状态

菜单栏使用从 App 图标提炼的八向分瓣环和中央窗口。图标为 18 × 18 pt 的单色 SVG 模板，由系统根据菜单栏背景和选中状态着色；外环在两种状态下保持一致。

| 中央窗口 | 含义 | 无障碍标签 |
| --- | --- | --- |
| 实心 | 已启用、辅助功能已授权、组合键配置有效，且窗口手势监听正在运行 | Ordo 正在运行 |
| 空心 | 上述条件尚未全部满足，例如暂停、未授权或监听尚未运行 | Ordo 未运行 |

空心表示窗口手势当前未运行，不代表 App 已退出。可从菜单打开主界面查看具体状态。

菜单栏图标与主 App 图标分别维护。主图标保留 Icon Composer 分层玻璃效果；菜单栏图标按小尺寸重新绘制，不包含背景、颜色渐变或阴影。查看[深浅色与两种状态的模拟预览](Artwork/MenuBarIcon/preview.png)，源文件位置及维护要求见[图标资源说明](Artwork/README.md)。

## 首次授权

1. 启动 Ordo，打开首次使用引导。
2. 点击“授权辅助功能”。只有这一步会触发系统授权提示。
3. 在“系统设置 → 隐私与安全性 → 辅助功能”中启用 Ordo。
4. 返回 Ordo；应用会自动检查权限并开始监听。

Ordo 只显式申请辅助功能权限，不会单独发起 Input Monitoring、屏幕录制或 Apple Events 授权。系统授权提示只会在用户点击“授权辅助功能”后触发。

从旧临时签名迁移到开发证书签名时，可能仍需在系统设置中手动移除旧 Ordo 条目并为 `build/Ordo.app` 重新授权一次。之后保持签名团队、Bundle ID 和安装路径稳定，连续更新两次并确认移动、缩放和排布可用，以验收权限延续性；仅构建或启动成功不代表权限验收通过。更新脚本不会重置 TCC 或修改系统权限数据库。

## 主界面与活动日志

主界面分为概览、窗口手势和活动日志三页。窗口手势页可分别修改三组组合键，并可开启或关闭松键后的排布动画；每组组合键只能包含 `⌘`、`⌥`、`⌃`、`⇧`，至少选择两个修饰键，且三组不能重复。配置使用 `UserDefaults` 保存在本机。

活动日志只在内存中保留本次运行最近 200 条记录，可复制或清除，退出后自动消失。日志记录运行、权限、监听和手势结果，但不记录窗口/App 身份、位置尺寸、鼠标位置、按键值或按键次数。

## 测试

更新脚本的隔离故障测试：`./scripts/tests/dev-update-tests.sh`。测试只操作 `build/` 内自建的假 App，覆盖并发拒绝、构建与验签失败、退出超时、替换和启动失败恢复，不操作真实 App 或系统权限。

标准套件可在未授予辅助功能权限时运行，其中真实 AX 窗口测试会跳过；测试宿主已获授权时，该项会实际查找、置前、移动和缩放窗口。运行时需留意桌面窗口遮挡及并行测试干扰，当前已知限制见[验证记录](docs/VALIDATION.md)。

完整测试命令：

```bash
xcodebuild test \
  -project Ordo.xcodeproj \
  -scheme Ordo \
  -destination 'platform=macOS' \
  -derivedDataPath "$PWD/build/TestDerivedData"
```

XCTest 覆盖组合键校验、会话状态、4 pt 启动死区、八向分类与迟滞、布局与多屏坐标、移动和缩放几何、活动日志，以及单窗口前置门控、模拟窗口写入失败和监听恢复边界。真实 AX 权限、Event Tap 与第三方 App 集成仍需人工验收。

菜单栏资源另外检查 18/36 px 渲染、原生加载尺寸、模板与矢量属性、外环一致性及中心实心/空心差异。模拟预览可用于检查图形；系统菜单栏的实际高亮、状态切换与可访问性仍需实机验收。

单窗口前置的主要验收场景：Typora 在前台，终端打开两个独立普通窗口，操作终端上次未获焦点的那个窗口。分别验证移动、缩放和排布后，只有目标窗口越过 Typora 并获得键盘焦点，另一终端窗口相对 Typora 的层级、位置和尺寸不变。检查焦点时不向终端发送测试命令；Finder、Safari、Xcode、Chrome/Electron、固定尺寸窗口和多屏另行回归。

## 项目结构

```text
Ordo/
├── App/       应用生命周期、状态协调、手势会话和预览窗口
├── Core/      可测试的手势模型、布局和坐标几何
├── System/    AX 窗口控制、CGEventTap 与屏幕信息
├── UI/        菜单栏、主界面、权限引导和排布预览
├── AppIcon.icon/ 主 App 图标的 Icon Composer 分层资源
└── Resources/ Asset Catalog，包含菜单栏模板 SVG
OrdoTests/     单元测试与系统层模拟测试
scripts/       本地更新入口、App 生命周期辅助程序与隔离故障测试
Artwork/       主图标可编辑源、概念稿与菜单栏模拟预览
docs/          带日期的验证结果与待验收事项
```

系统能力通过 `WindowControlling`、`ScreenGeometryProviding` 和 `EventSource` 与核心状态机隔离。AX 元素集中保存在串行 actor 中；鼠标移动事件合并至约 60 Hz。

## 隐私与边界

- 普通窗口手势监听为 listen-only，只订阅修饰键状态变化和鼠标移动，不阻断或修改系统输入。
- 不发送网络请求，不包含行为分析或遥测。
- 不支持原生全屏、跨 Space、Split View 或 Stage Manager 私有适配。
- 固定尺寸窗口、原生全屏窗口或拒绝 AX 写入的 App 可能无法管理；Ordo 会安全停止并显示状态。

仓库协作与验证约定见 [`AGENTS.md`](AGENTS.md)。
